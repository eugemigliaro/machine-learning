0. Dataset.​
Para este trabajo se utilizará el dataset Bank Marketing, basado en campañas telefónicas
realizadas por una institución bancaria portuguesa. El objetivo es predecir si un cliente
contratará o no un depósito a plazo fijo (y = yes/no) a partir de información demográfica,
datos de campañas previas y variables del contexto económico. La problemática representa un
caso típico de clasificación supervisada en datos tabulares: a partir de información disponible
antes o durante una campaña comercial, se busca estimar qué clientes tienen mayor
probabilidad de responder positivamente, permitiendo priorizar recursos de marketing.

https://www.kaggle.com/datasets/henriqueyamahata/bank-marketing


1. Preprocesamiento y análisis exploratorio

Se espera que realicen un análisis exploratorio básico que les permita entender el dataset
antes de entrenar los modelos. Este análisis debería incluir, por ejemplo, el balance de clases,
la distribución de algunas variables relevantes, la relación entre variables predictoras y la
variable objetivo, la presencia de valores faltantes o categorías poco frecuentes, y posibles
diferencias entre clientes que aceptan y no aceptan la oferta.

*El EDA no es solo una exploración de datos sino que debe utilizarse para tomar decisiones
concretas sobre el pipeline de Machine Learning. Por ejemplo, pueden justificar la exclusión de
alguna variable, decidir cómo tratar variables categóricas, aplicar escalado cuando
corresponda, agrupar categorías poco frecuentes, crear nuevas variables si consideran que
aportan información útil, o comparar el desempeño del modelo con y sin ciertas variables
problemáticas. Dado que no es el foco principal del TP, no se espera un análisis exploratorio
exhaustivo, pero sí que las observaciones realizadas durante el EDA tengan alguna
consecuencia sobre el preprocesamiento, la selección de variables o la interpretación de
los resultados.

*Es importante analizar críticamente variables que puedan introducir data leakage si se
interpreta como información que no debería estar disponible antes de realizar la llamada (y por
tanto del momento en el que nuestro modelo operaría en la aplicación real).

*Recuerden realizar la división entre entrenamiento y test antes de aplicar cualquier
transformación que pueda producir data leakage. Las transformaciones aprendidas de los
datos, como escalado, imputación o codificación, deben ajustarse utilizando únicamente los
datos de entrenamiento dentro del pipeline correspondiente.
